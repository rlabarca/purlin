## How a slow test is kept from starting

`frameworks.leave_out` adds the tool's own option to the command in the `tests` setting, after
`{files}` or at the command's end. Nothing is added to the test or the suite.

| Tool | Option | Checked against the real tool |
|---|---|---|
| pytest | `--deselect <file>::<Class>::<test>` | yes, in `run_script PROOF-275`, `279`, `280` |
| vitest 3.2.7, jest 29 | `--testNamePattern '^(?!(?:.* )?(?:<title>|...)$)'` | by hand, in a scratch project; the report lists the test as skipped |
| dotnet 8, xUnit | `--filter 'FullyQualifiedName!=<ns>.<Class>.<Method>&...'` | by hand, on `dev/fixtures/reports/dotnet`: a fact, a theory and a nested class left out |
| go 1.27.1 | `-skip '^(?:<Name>|...)$'` | by hand; needs Go 1.20 |
| sql, shell, any `exit` suite | the file is not run | yes, in `run_script PROOF-277` |

Where it cannot be, the test is started, its result counts, and the run prints
`Started <n> slow tests in the <suite> suite: its command gives Purlin no way to leave one test out.`:
a command that is none of these tools'; one that already carries the option; one with no
`{files}` that pipes, chains or redirects; a vitest or jest test whose full title another test
that is not slow shares (the pattern matches in every file) or whose title a table fills in; a
go test whose name a test that is not slow shares in another package. Two cases are not
announced: an NUnit `TestCase`, whose name carries its arguments, is not matched by the filter
and simply runs and counts; and a test in a file with no test comment that shares a slow jest,
vitest or go test's name is left out with it, which Purlin does not see. A test that carries a
slow proof's comment and another proof's comment is started, since the other proof needs it.
