Rules: dev/plans/lanes/_rules.md (read in full); the phase 9 rules in dev/plans/lanes/9B.md (rule tags, the author flag)

Run 34840363131 of `.github/workflows/purlin.yml` (with lane F10's diagnostics, without
F11) showed, on `ubuntu-latest`:

```
11:52:31 Running the pytest arm.
11:53:54 Running the shell arm.
12:53:54 Ran pytest, shell on 37 feature(s) at tier all.
Evidence is missing: the pytest runner exited 1.
Evidence is missing: the shell runner timed out after 3600 s.
Evidence is missing: 561 marker(s) produced no proof entry: approvals PROOF-1 (pytest), ...
Record committed as ci.
37 features, 490 rules. Proof ready 69, Reviewed 421.
```

and on `windows-latest` the pytest arm ran 8 minutes and left 7 rules at Proof ready, the
shell arm exited 1 at once (before F10's skip landed there). So on Linux the pytest arm
dies in 83 seconds having written almost nothing, and the shell arm blocks for the whole
hour; on this Mac both are green in minutes. The arms' output is captured to
`.purlin/runtime/run.log` on the runner and never reaches the job log, so the cause is
invisible. Run 34842281168 (with F11) is running or finished by the time you start:
`gh run view 34842281168` and its job logs are your second data point.

## 1. Make the cause visible, always

In `scripts/run/purlin_run.py`: when an arm exits non-zero or times out, print the last
60 lines of that arm's captured output to stdout under a heading `--- <arm> output (last
60 lines) ---`, flushed, before the `Evidence is missing` lines; and under `--ci`, copy
each arm's full output into the published dashboard directory (`scripts/run/ci.py`
`publish_dashboard` gets an extra `logs` argument, or the run writes
`<publish_dir>/logs/<arm>.log` itself) so the `purlin-dashboard` artifact carries it.
Tests in `dev/test_run_script.py` for both, with proof markers on a new rule of
`specs/run/run_script.md` (`[risk: medium] [origin: eng]`).

## 2. Find the Linux causes

Reproduce on this Mac with the runner's shape: a fresh `HOME` and `npm_config_cache`
(empty caches, so `npx`/`npm` behave as on a runner), `CI=true GITHUB_ACTIONS=true`, no
`dotnet` on PATH, `PATH` without this repository's `.venv` (the runner installs only
`requirements.txt`, so anything the tests import beyond pytest and playwright is missing
there: grep every `import` in `dev/test_*.py` and `dev/conftest.py` against
`requirements.txt` and against Python's standard library), stdin from `/dev/null`, and
run: `python3 -m pytest -q` (the pytest arm), then `bash proof_plugins.test.sh` and `bash
init_e2e.test.sh` under a 10-minute cap each. Read `dev/test_init_e2e.sh` and
`dev/test_proof_plugins.sh` for anything that waits: `npm install`/`npx` on a cold cache
(they can prompt or fetch for minutes), `npm ci` on a lockfile, a `git push` to a remote
over the network, `gh`, `claude`, `sleep` loops, `read`. Then read run 34842281168's
Ubuntu log (F10's per-arm lines are there) and, once item 1 is in, the next run's artifact
will carry the arm output; if the cause is still not reproducible here, the fix is
whatever makes the arm state its reason and stop within minutes (a cap on every network
command in the shell suites, a skip when `npm` has no cache and no network, a `timeout`
around `npm install`).

Fix what you find, keep this Mac green, and list every cause in the DONE note.
