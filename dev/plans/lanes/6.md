## B8. Dashboard `scripts/report/` (~900 lines of page, ~120 lines of build)

Three screens, matching the kit's information architecture on the new model: **Board**
(gate and staleness in the top bar; stat tiles for the seven states; a risk-by-state grid
when risk tags exist; grouped spec table with coverage bar, state pill, test strength,
latest record label, approvals, re-verify pending; rows expand to rules), **Rule** (rule,
proof, test, test strength, latest record, approvals, the brief summary, links to the git
host), **Review list** (CI's list by risk with the reason per rule). Filters: high risk not
approved, stale, no negative case, low test strength, open items. Design anchor rows show a
thumbnail. Columns appear as their artifacts exist. Payload schema 4 from `payload.py`,
loaded the way the current page loads `report-data.js` (`file://` safe). Both themes via the
tokens; the toggle sets `data-theme`. No emoji, no icons, no shadows. Acceptance includes a
check that no hex colour appears in the page outside the inlined token block.

### Phase 6: dashboard on the design system (Opus 5, 1 lane)

`scripts/report/src/` and `dev/build_report.py` produce `scripts/report/purlin-report.html` (target 900) per B8, plain HTML and CSS on `design/tokens/`, both themes, the three screens: gate and staleness in the top bar; seven-state strip; risk-by-state grid; feature table (spec, risk,
coverage, state, latest record label, approvals, re-verify pending); the review list view;
filters (high risk not approved, stale, no negative case, low test strength, open action
items); per-feature drill-down with rules, proofs, brief summary, git host links; design
anchor thumbnails. Columns appear as artifacts exist. Local data from `sync_status` and
the digest hook (gitignored); CI publishes page plus data as the `purlin-dashboard`
artifact. Acceptance: `dev/test_purlin_report.py` under 600 lines, including the no-raw-hex check and a both-themes render; one screenshot per process and per screen for the docs.

## Outputs

- `scripts/report/src/`: the page in parts (`page.html` shell, `board.js`, `rule.js`,
  `review.js`, `filters.js`, `theme.js`, `styles.css`), plain HTML, CSS and JavaScript, no
  framework, no build-time dependency, no external request.
- `dev/build_report.py` (~120): inlines `design/tokens/*.css` as one `<style
  id="purlin-tokens">` block, the page CSS, the logo data URI and the scripts into the
  single `scripts/report/purlin-report.html` (target 900 lines), and copies it to the root
  `purlin-report.html`. Run it; commit the built page (a consumer receives the built file
  from `purlin:init`).
- The page: three screens per B8 (Board, Rule, Review list); filters (high risk not
  approved, stale, no negative case, low test strength, open items); columns appear only
  when their artifacts exist in the payload (no risk tags: no risk grid; no records: no
  record column; no approvals: no approvals column); the top bar shows the gate and the
  data's age; state pills for the seven states with the shared state hues (pass, warn,
  fail, neutral); test strength as an integer percent or `n/a`; design anchor rows show
  the thumbnail of the first file in `designs/<anchor>/` when present; links to the git host
  built from the payload's remote URL when one exists. Both themes through the tokens, the
  toggle sets `data-theme`, `data-surface="product"` on the page. No emoji, no icon set
  (`▶ ▼ ▲ →` only), no shadows, no gradients, no raw hex colour outside the inlined token
  block. Copy per `design/readme.md`. A payload with an older `schema_version` shows one
  notice line naming `purlin:status`, nothing else.
- `dev/test_purlin_report.py` (under 600 lines): the build is reproducible (running
  `dev/build_report.py` twice gives the same bytes), the no-raw-hex check (every
  `#[0-9a-fA-F]{3,8}` in the built page sits inside the token block), a both-themes render
  through the headless browser with a fixture payload for each of the three processes
  (solo at `tested`, team at `recorded`, regulated at `approved`), the columns-appear rule,
  each filter, the older-schema notice. Fixture payloads under `dev/fixtures/report/`.
- Screenshots for the docs, captured from the fixtures: `docs/images/dashboard-solo.png`,
  `dashboard-team.png`, `dashboard-regulated.png` (Board), `dashboard-rule.png`,
  `dashboard-review-list.png`, each in the dark theme at 1440 wide; phase 8 links them.
