# Lane F19: CI's approvals and briefs travel with its record

Design: dev/plans/evidence-workflow.md (A4 "How CI writes", A5, B4, B7)
Rules: dev/plans/lanes/_rules.md (read in full); the phase 9 rules in dev/plans/lanes/9B.md (rule tags, the author flag)

Every CI run on this repository prints `Record committed as ci.` and then `Auto-approved 77
low-risk rules; 421 briefs written`, and the branch holds no `specs/**/*.approvals/` file
at all (`git ls-files 'specs/*/*.approvals/*'` is empty after seven runs). The runner's
table says `Approved 77`; a checkout says `Recorded 482`. A4 says CI creates one commit
"containing the record and any CI auto-approvals"; B7 puts the brief beside the approval
it informs. Both are written after the commit and never added to it.

## Change

- `scripts/run/purlin_run.py` `--ci`: run auto-approval and the briefs before the commit,
  and hand `commit_records` every path they wrote (the `<RULE-N>.<hash8>.ci.json` files
  and the `<RULE-N>.<hash8>.brief.json` files under `specs/<category>/<feature>.approvals/`)
  together with the record paths; one API commit, message unchanged. The developer path
  (`--commit`) writes no approvals and is unchanged. `scripts/run/records.py`
  `commit_records` already takes a path list; make sure the CI path sends blobs for every
  path given and that the retention deletions still travel.
- The brief files: the plan's B7 says the brief sits beside the approval; keep that, and
  make sure a brief for a rule that is not auto-approved is still written and committed
  (the review list is what QA works from, and it is read from the branch).
- The Recorded, Reviewed and Approved states are then reachable from any checkout. Confirm
  with a test in `dev/test_run_script.py` that a `--record --ci` run with a fake
  `commit_records` receives the approval and brief paths alongside the records (proof
  marker on a new rule of `specs/run/run_script.md`, `[risk: high] [origin: eng]`: an
  approval that exists only on a runner is evidence nobody can read), and a test in
  `dev/test_records.py` that the CI commit's tree carries a path outside `.purlin/records/`.
- `references/formats/record_format.md` or `approval_format.md` and `docs/running-and-records.md`:
  correct any sentence that describes the CI commit's contents.
- The retired branch rule in A4 ("restrict file paths `.purlin/records/**` and
  `specs/**/*.approvals/*.ci.json`") already anticipates this; `references/hard_gates.md`
  states it; leave both.
