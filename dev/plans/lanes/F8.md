## 1. The dashboard artifact comes up empty

`scripts/run/purlin_run.py --ci` calls `scripts/run/ci.py` `publish_dashboard(project_root,
<project>/.purlin/runtime/report)` while `templates/purlin.yml` line 90 uploads
`${{ runner.temp }}/purlin-dashboard` (and `templates/purlin.azure-pipelines.yml` its own
path). The two never meet, so the `purlin-dashboard` artifact CI attaches to the PR would be
empty. Fix, simplest: `publish_dashboard` defaults its output directory to
`$RUNNER_TEMP/purlin-dashboard` when `RUNNER_TEMP` is set (GitHub), to
`$AGENT_TEMPDIRECTORY/purlin-dashboard` when that is set (Azure DevOps), and to
`.purlin/runtime/report` otherwise; the run script passes nothing and prints the directory
it published to; both templates upload the matching path (check the ADO template's upload
step names the same directory the ADO variable gives). Add one test in
`dev/test_records.py` (where `ci.py`'s tests live) for each of the three cases, and one in
`dev/test_consumer_ci.py` asserting the rendered workflow's upload path equals the
directory `ci.py` names under `RUNNER_TEMP`. Update the sentence in
`docs/running-and-records.md` or `docs/dashboard.md` only if either names a path that is now
wrong (grep them).
