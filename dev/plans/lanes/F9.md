one proof `@env(windows)`; every other proof is untagged and "satisfied by any OS", but
the CI job that proves them all and writes the record that counts has to exist, and C4
item 4 requires a Linux and a Windows job. `scripts/run/workflow.py` `render_workflow`
renders only the tagged OSes. Fix: the matrix always carries `ubuntu-latest` first, then
the tagged OSes in `ORDER`, deduplicated (`['windows']` gives `ubuntu-latest, windows-latest`;
`[]` gives `ubuntu-latest`; `['linux']` gives `ubuntu-latest` once). Update `dev/test_consumer_ci.py`
and `dev/test_records.py` (wherever `render_workflow` is asserted), the template comment if
it says otherwise, `specs/run/records.md` if a rule states the old behaviour (edit that
rule's text; keep its number), and the sentence in `docs/running-and-records.md` if it
describes the matrix.

## 2. The upgrade keeps frameworks the tree does not have

Output: `wrote jest.config.js`, `wrote vitest.config.ts`. This repository's old
`.purlin/config.json` says `test_framework: pytest,jest,shell,vitest` from a release that
listed every plugin; the tree has no `package.json`, so every run prints `the jest runner
exited 1`. `scripts/init/update.py` `_apply_config` (line 271) carries the old list through
`resolve_gate`, and `scripts/init/scaffold.py` (lines 559 to 570) keeps a recorded list
untouched. Fix, in both: when the recorded list names a framework that
`frameworks_module.detect_frameworks(root)` does not find and the tree carries no wiring for

`pytest.ini` or `pyproject.toml` for pytest, no `*.sql` for sql), drop it and print one line
`dropped <name> from test_framework: nothing in the tree runs it`; a recorded framework the
tree does carry stays even when detection would not have picked it. Tests in
`dev/test_init_update.py` (the 0.10-dev fixture lists jest, vitest and has no package.json:
assert the migrated config reads `pytest,shell` and the line prints) and
`dev/test_init_scaffold.py` (a `--gate` change on a project whose config names a framework
the tree lacks). `specs/init/update.md` and `specs/init/scaffold.md`: add one rule each
with its proof, tagged `[risk: medium] [origin: eng]`, at the next free number.
