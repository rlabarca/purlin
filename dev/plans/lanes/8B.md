## Rules every phase 8 lane follows

- Every doc opens with one line saying who it is for. Plain voice: short sentences, second
  person for the reader, third person for the system, exact numbers, limits stated, no
  superlatives, no rhetorical questions, no emoji. Sentence case. Commands, ids, paths and
  shas in backticks.
- A diagram is mermaid with the init block from `docs/_mermaid.md` pasted at the top of the
  fence (lane 8D writes that file; until it lands, use the block given below verbatim so
  every lane pastes the same one). At most one diagram per doc, only where it shows a
  mechanism. No images except the five dashboard screenshots.
- Nothing cites `dev/`, this repository's own `specs/`, or a script by a path outside
  `scripts/`; a consumer's copy has none of them. Scripts are named as
  `${CLAUDE_PLUGIN_ROOT}/scripts/...` or by the skill that runs them.
- Both ways Purlin is loaded appear wherever install or CI is explained: `claude
  --plugin-dir <checkout>` and the marketplace install (the plugin under
  `~/.claude/plugins/cache/purlin/purlin/<version>/`; a consumer's CI runner clones Purlin
  at the pinned tag because it has no plugin).
- Retired vocabulary never appears (audit, gauge, HOLLOW, PROVABLE, receipt, platform,
  `@on`, mode, mutation score, caught score, records branch, Pages, forge, queue, CODEOWNERS,
  approver rule). "Mutation testing" is named once in the whole doc set, in
  `docs/running-and-records.md`. The git host is "GitHub" or "Azure DevOps".
- Length ceilings from the outline are ceilings. Do not pad.
- Links between docs use the file names in the outline; no lane renames a doc.
