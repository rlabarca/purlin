# Lane F16: the Latest record column says what each operating system's record found

Design: dev/plans/evidence-workflow.md (A4 "Label from git", "Cross-platform validation"; B8); design/readme.md "Content fundamentals"
Rules: dev/plans/lanes/_rules.md (read in full); the phase 9 rules in dev/plans/lanes/9B.md (rule tags, the author flag)

On this repository's board every spec row reads `ci linux` in the Latest record column,
because the column shows the single newest record per feature and the newest is the
Linux job's, which finished last. That Linux record holds failures for nearly every proof
while the Windows record passed, and the column cannot tell the reader. A record's
existence is not its result.

## Change

- The column shows one entry per operating system that has a counting record at the
  current scope for that feature (the payload's `records[<feature>]` map keyed by OS, `""`
  for a record without an OS): `<os> <result>` in the result's tone (`passed` pass hue,
  `failed` fail hue), entries joined by ` · `; the label is shown only when it is not `ci`
  (`developer passed`, `local failed`), since CI is the expected writer. A feature with no
  record shows `—` as now. The tooltip (`title`) carries the record's timestamp and path.
- If `payload.records[<feature>][<os>]` does not already carry `result` (`pass`/`fail`
  over its proofs) and `label`, add them in `scripts/mcp/purlin/payload.py` (read
  `records.proof_statuses` and `record_label`), keeping every existing field; one test in
  `dev/test_mcp_server.py` on a new proof of `specs/mcp/states.md` (`[risk: medium]
  [origin: eng]`).
- The Rule screen's "Latest record" line follows the same rule (per OS, with result).
- `dev/test_purlin_report.py`: adjust the column tests; add one with a fixture where the
  Linux record fails and the Windows record passes, asserting both appear with their
  words; tag on a new proof of `specs/dashboard/purlin_report.md` (`[risk: low] [origin:
  eng]`), editing the rule that describes the column (keep its number). Update the report
  fixtures under `dev/fixtures/report/` as needed.
- Rebuild, regenerate the screenshots the change touches, refresh the root copy;
  `docs/dashboard.md` sentence on the column.
