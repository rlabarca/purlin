## Inputs

- `tools/PM/purlin-anchor-userstories.md` (362) and `tools/QA/purlin-qa-report.md` (370):
  the current Claude Desktop skills, for the frontmatter shape and the packaging only; the
  content is retired.
- `dev/pack_tools.sh` (50): packs each `.md` into the sibling `.skill` file.
- `scripts/report/scan.py` (lane 2C): `--repo <url> [--ref <branch|tag>]`, the seven-state
  rollup and "N commits behind the latest record"; the QA tool is built on it.
- `references/formats/spec_format.md` (lane 1A) for the rule and proof shapes with tags;
  `references/review_criteria.md` (lane 3B); `references/purlin_commands.md` (lane 4B).

## Outputs

- `tools/PM/purlin-anchor-userstories.md` (~150): for a PM with no checkout, in Claude
  Desktop with a GitHub or Azure DevOps connector: takes a repo URL and a path (the project
  itself or an anchor repo), drafts or edits a spec or anchor from a sentence, PRD, ticket,
  pasted criteria or uploaded design images (committed into `designs/<feature>/`), writes
  rules with `[criterion: <id>] [risk: ...] [origin: pm]`, never silently edits a rule owned
  by `eng` or `qa` (it leaves a PR comment proposing the change), opens the PR, and tells
  the PM what `drift pm` and the dashboard artifact will show after CI runs.
- `tools/QA/purlin-qa-report.md` (~120): for QA in Claude Desktop: runs `scan.py` against
  the repo URL, produces the triage report ordered by risk (the review list, never the
  whole rule list), opens PRs with proof edits and approval files, and explains what counts
  as an approval under each gate (signed commit, approver list).
- Both `.skill` files repacked with `bash dev/pack_tools.sh`.
