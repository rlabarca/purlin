## The defect (found by lane 5A's end-to-end walk)

A record is written per feature (lane 2A's decision, `.purlin/records/<feature>/...`), and
the package reader, `references/formats/record_format.md` and `states._record_verdict`
all treat the record's `scope_tree` as one string, the hash `specs.scope_tree(root, scope)`
returns for that feature. But `scripts/run/purlin_run.py` `build_record` (lines 470 and
512) writes `scope_tree` as a dict `{feature: hash}`, and `dev/test_run_script.py:476`
asserts that dict. A dict never equals the string, so `scope_matches` is always false;
`at_head` is also false because CI commits its record on top of the commit it observed,
which is the case the scope tree exists to cover. Nothing reaches Recorded. Evidence from a
temp project: record `scope_tree` = `{"greeting": "6f4ba7fc..."}`,
`specs.scope_tree(root, ["greeting.py"])` = `"6f4ba7fc..."`, rule state `Tested`, gate
output `Not recorded (1): greeting RULE-1`.

## Fix

1. `build_record` writes `scope_tree` as the string for the record's own feature (the
   record is per feature; nothing else lives in it). Update `dev/test_run_script.py` to
   assert the string; grep `scripts/` and `dev/` for any other reader of the dict shape.
2. `dev/test_init_e2e.sh`: the three steps lane 5A skipped ("recorded and approved cannot
   be met") become assertions: under `recorded` the gate exits 0 once the ci-labelled
   record exists; under `approved` it exits 1 until a signed high-risk approval by an
   approver on the list exists, then 0. Read the script's skip lines for exactly what was
   skipped.
3. While there: confirm end to end on a temp Python project that `purlin_run.py --all
   --record --commit` followed by `sync_status` shows the rule Recorded (label
   `developer` counts under `tested` only, so use `--ci` with the fake commit the e2e uses,
   or set the gate to `tested` and check Tested versus Recorded per A4). Put that walk in
   `dev/test_run_script.py` as one test if it is not already covered.
