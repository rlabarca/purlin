# Feature: skill_route

> Description: What `skills/route/SKILL.md` must say. Route shows model routing and turns it on
>   and off: it writes the project's tier table, one project skill per Purlin skill carrying that
>   skill's model, and the session settings, and starts no script and no model to decide or check
>   anything.
> Scope: skills/route/SKILL.md
> Stack: markdown, Claude Code skill definition
> Highest-Rule: 13
> Highest-Proof: 20

## Rules

- RULE-1: The skill names the commands `purlin:route`, `purlin:route on` and `purlin:route off` and the path `references/formats/routing_format.md`, and names no script under `scripts/`
- RULE-2: In the part `On`, a **Stop and ask** that names the model each tier gets comes before the file is written
- RULE-3: The skill says `.purlin/routing.local.json` holds `tiers` alone and that git ignores it
- RULE-4: On writes `"agent": "purlin:purlin"` and the `balanced` model into `.claude/settings.json`, keeping every other setting, and Off takes the two out again
- RULE-5: On and Off each commit `.purlin/routing.json`, `.claude/settings.json` and `.claude/skills/` under the `chore:` prefix
- RULE-6: The skill says `purlin:route on` starts no model, so a model the harness does not know fails at the first skill that names it
- RULE-7: On writes, for each skill that names a tier, `.claude/skills/<skill>/SKILL.md` as the format's part "The project skills" gives it, and never writes over a file there whose description does not open on `Generated by purlin:route`
- RULE-8: Off removes each project skill whose description opens on `Generated by purlin:route`, and no other
- RULE-9: The skill has a part `Gotchas` saying that `purlin:route on` writes nothing before the person answers, that `/purlin:<skill>` runs on the session's model, that a skill another skill runs or a request in plain words uses the model already running, and that routing works in this session, which keeps its own model; its last message tells the person to type `/<skill>`, not `/purlin:<skill>`
- RULE-10: On names the part of `references/formats/routing_format.md` to read at the step that needs it: "The two tables" at the step that shows each skill's tier, "The file" at the step that writes the routing file, and "The project skills" and "The hand-off message" at the step that writes the project skills
- RULE-11: On copies each project skill's template exactly, changing only `<skill>`, `<tier>`, `<model>` and the hand-off message's lines, and leaves no `<` placeholder in a file it writes
- RULE-12: On opens on a checklist of its steps, from the answer to the commit
- RULE-13: On checks what it wrote before it commits: each project skill's model against the table, no project skill for `init`, the session settings merged; and fixes and checks again until every check passes
