# Feature: purlin_report

> Description: The board: one HTML file that shows where every rule stands.
>   It opens from disk and as a build artifact, reads `.purlin/report-data.js`
>   beside it, and carries three screens: the board, one rule, and the review
>   list CI prepared. It is assembled from the parts under `scripts/report/src/`
>   by `dev/build_report.py`, which inlines the design tokens so every colour on
>   the page resolves to one block and both themes ship in the same file. The
>   screenshots the docs embed are captured from the same fixture payloads the
>   tests render.
> Scope: scripts/report/src/page.html, scripts/report/src/styles.css, scripts/report/src/theme.js, scripts/report/src/filters.js, scripts/report/src/board.js, scripts/report/src/rule.js, scripts/report/src/review.js, scripts/report/src/app.js, scripts/report/purlin-report.html, dev/build_report.py, dev/capture_doc_screenshots.py
> Stack: html/css/javascript, no framework and no build-time dependency, design tokens inlined by a python assembler

## Rules

- RULE-1: The build is a pure function of its parts: two runs over unchanged sources write the same bytes [risk: low] [origin: eng]
- RULE-2: The build writes one file of at most 1200 lines and copies it to the project root, where the data file and the design files a spec names resolve beside it [risk: low] [origin: eng]
- RULE-3: Every colour the page uses is written inside the one inlined token block, and no colour literal appears anywhere else in the file [risk: medium] [origin: eng]
- RULE-4: The page carries no shadow, no gradient and no emoji [risk: medium] [origin: eng]
- RULE-5: The page asks nothing of anything outside itself: no stylesheet link, no style import, no fetch, and no source or link address on another host [risk: high] [origin: eng]
- RULE-6: Affordances are unicode glyphs and the page draws no icon set [risk: low] [origin: eng]
- RULE-7: The board heading states how many rules meet the gate out of how many there are, names that gate and states the failing count, the top bar states the gate and how old the data is, and every spec in the payload has a row [risk: medium] [origin: eng]
- RULE-8: The strip above the table carries one tile per bucket the gate reaches, `Untested`, `Failing` and `Passed` at every gate, `Strong` at `strong` and `Signed` at `signed`, each showing that bucket's count from the payload's summary with its label set in capitals, and at `signed` a `Stale` flag card beside them [risk: medium] [origin: eng]
- RULE-9: A column exists only where the gate reaches it: `Spec`, `Rules`, `Spec status`, `Tests` and `Last run` at every gate, `Strength` and `Strong` at `strong`, `Signed` at `signed`. The board carries no risk column and no grid of rules by bucket at any gate [risk: medium] [origin: eng]
- RULE-10: A spec row opens to the rules it owns and closes again on the next click [risk: low] [origin: eng]
- RULE-11: A row whose spec pins a single image file shows that image as a thumbnail beside the name [risk: low] [origin: eng]
- RULE-12: Both themes ship in the page. It sets no surface override, so it opens dark on the brand navy ground, and the toggle swaps the ground, the ink and the mark to the other theme, and swaps back [risk: medium] [origin: eng]
- RULE-13: The board offers the filters the gate reaches, `Untested` and `Failing` at every gate, `Weak` at `strong`, `Unsigned` and `Stale or held` at `signed`, and each narrows the table to the rules it accepts [risk: medium] [origin: eng]
- RULE-14: Filters compose: a rule shows only where every set filter accepts it, a combination nothing matches says so in place of the table, and unsetting them restores every row [risk: medium] [origin: eng]
- RULE-15: The rule screen states the rule text, the spec status, one row per cell the gate reaches carrying that cell's word and its reasons, and each proof with its tier and the test file and test name that carry the proof marker; at `strong` and above a Brief panel gives the test strength beside the minimum, each free-check finding in one sentence naming the proofs that carry it, what the model review observed, and whether it settled [risk: high] [origin: eng]
- RULE-16: Where the payload names a git host the page can address, the spec file, the record and each signature file are links to that host at the payload's commit; where it names no remote the same paths stay plain text and nothing on the screen is a link [risk: medium] [origin: eng]
- RULE-17: A rule whose proof names an operating system that no counting record came from says so on its screen, naming that system, rather than reading as proved [risk: high] [origin: eng]
- RULE-18: The review list names how many rules need a person, summarises each risk with its counts of unsigned, stale, held, manual test and manual audit, and groups the rows high risk first with a count per group and stale or held first inside a group; every row carries the feature, the rule id, the rule's text cut to one line, the risk tag, the blocking cell's word as the pill the board draws, and opens the rule screen when clicked. Under the `passed` gate the review list is not offered at all [risk: high] [origin: eng]
- RULE-19: An empty review list says what puts a rule on it instead of showing nothing [risk: low] [origin: eng]
- RULE-20: A payload written for another schema version shows one notice naming the command that rewrites it, and no tiles, no table and no tabs, rather than rendering fields it cannot read [risk: high] [origin: eng]
- RULE-21: With no data file at all the page names the command that writes one [risk: low] [origin: eng]
- RULE-22: The notice that the working tree has uncommitted changes belongs to the board and appears on no other screen [risk: medium] [origin: eng]
- RULE-23: The screenshots the docs embed are captured from the fixture payloads the tests render, not from whatever the checkout holds, and land in `docs/images/` [risk: low] [origin: eng]
- RULE-24: The tabs read Board, then the review list where the gate offers one, then the open rule last, and the open rule's tab stays clickable while its screen is showing [risk: low] [origin: eng]
- RULE-25: The rule screen carries one link back at its top which closes the rule and returns to the screen the rule was opened from, reading `← Review list` from the review list and `← Board` from the board [risk: low] [origin: eng]
- RULE-26: A rule that is not signed names the command that signs it, `purlin:sign <feature> <RULE-N>`, set in the monospace face, and states that a signature is a signed commit this page can only read back; a signed rule names who signed it instead. Below the `signed` gate the panel is absent [risk: low] [origin: eng]
- RULE-27: Coming back to a tab whose data is more than 60 seconds old reloads the page, and the screen and the open rule survive that reload [risk: low] [origin: eng]
- RULE-28: The freshness line in the top bar is a button carrying that same age text, styled as the theme button is, and pressing it reloads the page [risk: low] [origin: eng]
- RULE-29: The age in the top bar recomputes every 60 seconds from the stamp the payload already carries, reading the data file zero further times [risk: low] [origin: eng]
- RULE-30: A review row states the blocking cell's word and that cell's reasons as the payload writes them; where the cell carries no reason of its own, the row reads the entry's `why` tokens as sentences instead [risk: low] [origin: eng]
- RULE-31: The `Last run` column and the rule screen's last run line carry one box per operating system, in that system's newest record's result tone and grey where it has no record, each carrying its label, whether it passed or failed, its timestamp and its path as a tooltip; beside the boxes both read the newest record's source and age, or the source the passed cells name where no record exists, or `—` where neither exists [risk: low] [origin: eng]
- RULE-32: At the `signed` gate the board shows a `Stale` flag card beside the tiles carrying the summary's stale count, in the fail tone when it is above zero, and the heading line names the summary's failing count as `<N> failing` [risk: medium] [origin: eng]
- RULE-33: Every column heading of the spec table starts where its column's cells start in every row, so a wide cell never pushes its row's columns out of line with the headings [risk: medium] [origin: eng]
