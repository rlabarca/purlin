# Feature: ai_helper

> Description: The helper a test of an AI proof starts, `scripts/ai/purlin_ai.py`. `run` asks
>   one model through the `claude` program, either in a real session with one skill or plugin
>   loaded, in a copy of a sample, or with a prompt's instructions as the system prompt of one
>   bare call, and writes what came out into one folder: the reply, the transcript, the files the
>   session wrote or changed, and the helper's own record. `record` takes an output the project's
>   own test made. `grade` shows a grader the proof's sentence and the output and prints its one
>   line. The test asserts on the folder; the run reads the record. A model that gives no answer
>   leaves the record alone, saying why, so the run can read the proof as `not run`.
> Scope: scripts/ai/purlin_ai.py
> Stack: python/stdlib (json, subprocess, shutil, tempfile, re)
> Highest-Rule: 36
> Highest-Proof: 62

## Rules

- RULE-1: `run` takes exactly one of `--skill <folder>`, `--plugin <folder>` and `--instructions <file>...`, exactly one of `--input <file>` and `--say "<text>"`, and `--project <folder>` beside `--skill` or `--plugin` alone; any other use prints the usage text and one line naming what is wrong on standard error, writes nothing, starts no `claude` and exits 2
- RULE-2: An argument a mode does not have is named on one line after the usage text, `purlin_ai.py: unexpected argument <it>`, and the helper exits 2
- RULE-3: A path the command line names that is not there, a folder given as a skill that holds no `SKILL.md` or a file that cannot be read, is named on one line of standard error with no usage text; nothing is written, no `claude` is started and the helper exits 2
- RULE-4: With `--instructions` the program started is `claude -p --output-format json --max-turns 1 --tools "" --strict-mcp-config --safe-mode --setting-sources "" --disable-slash-commands --no-session-persistence --model <the model PURLIN_AI_MODEL names> --system-prompt <the files' text, a blank line between two>`, in an empty folder outside the project that is removed after
- RULE-5: What is said, the text after `--say` or the text of the `--input` file, is the whole of what `claude` reads on its standard input and is in none of its arguments
- RULE-6: After a `run` with `--instructions` the folder `PURLIN_AI_OUT` names holds `reply.md`, the `result` of the JSON the program printed; `transcript.jsonl`, that JSON on one line; an empty `files/`; and `purlin.json`
- RULE-7: A `run` or a `record` that made an output prints that folder's path alone on standard output, nothing on standard error, and exits 0
- RULE-8: The `purlin.json` of a run the model answered reads `made` `helper`, `model` the model asked, `reached` true and `why` null, and holds no other key
- RULE-9: With `--skill` or `--plugin` the program started is `claude -p --output-format stream-json --verbose --setting-sources "" --no-session-persistence --dangerously-skip-permissions --model <the model> --plugin-dir <folder>`, the folder being the plugin's own for `--plugin`
- RULE-10: A skill is loaded as a plugin of its own, made outside the project and outside the session's folder: it holds `.claude-plugin/plugin.json`, naming the plugin after the skill's folder, and the skill's files under `skills/<the folder's name>/`, and it is removed when the session ends
- RULE-11: The session is started in a copy of `--project`, or in an empty folder where none is given, made under the system's temporary folder and outside the project; the copy is removed when the session ends and the sample is left as it was
- RULE-12: After a session `reply.md` holds the `result` of the last `result` line the program printed and `transcript.jsonl` every line it printed
- RULE-13: After a session `files/` holds each file of the copy that is new or whose bytes differ from the sample's, at its path in the sample, and no other file; a file the session deleted leaves no trace
- RULE-14: At the top of the copy, `.git/` is left out of `files/`, and so is `.claude/` where the sample held no such folder
- RULE-15: The session is started without `PURLIN_AI`, `PURLIN_AI_MODEL`, `PURLIN_AI_OUT`, `PURLIN_AI_REPLAY` and `PURLIN_PROJECT_ROOT` in its environment
- RULE-16: A session is given 1800 seconds
- RULE-17: With no `claude` on the path, `run` writes `purlin.json` with `reached` false and `why` reading `claude is not on PATH`, writes nothing else, prints `purlin_ai.py: no answer from <model>: <why>.` on standard error and nothing on standard output, and exits 2
- RULE-18: A `claude` that exits with an error reads `why` `claude exited with an error`, and one that prints no result, or one that reports an error, reads `claude gave no answer`; either way the folder holds `purlin.json` alone and the helper exits 2
- RULE-19: A session that runs past its limit reads `why` `claude timed out after <n> s`, the folder holds `purlin.json` alone and the helper exits 2
- RULE-20: Where the program itself names the cause, `why` carries its first sentence after the cause and `: `: the `result` of a result that reports an error, else the first line of its standard error where it exited with an error
- RULE-21: A `run` or a `record` into a `PURLIN_AI_OUT` folder that already holds an output, or the record of a run no model answered, starts no `claude`, changes nothing in the folder, prints `purlin_ai.py: <folder> already holds an output. One test makes one output: call run or record once.` on standard error and exits 1
- RULE-22: Under `PURLIN_AI_REPLAY`, `run` and `record` print that folder's path and exit 0, start no `claude` and write nothing, in that folder or in the one `PURLIN_AI_OUT` names
- RULE-23: With no `PURLIN_AI_OUT`, the output goes to `.purlin/runtime/ai/by-hand/` of the project the helper is started in or under, emptied first
- RULE-24: With no model named, `run` and `record` print `purlin_ai.py: PURLIN_AI_MODEL names no model. Set it to the model to ask, then run this again.` on standard error, start no `claude`, write nothing and exit 2
- RULE-25: `record --from <folder>` copies that folder's `reply.md`, `transcript.jsonl` and `files/` into the output folder, and no other file of it; a folder holding `reply.md` alone is enough
- RULE-26: The `purlin.json` `record` writes reads `made` `project`, `reached` true, `why` null and `model` the one `--model` names, or the one `PURLIN_AI_MODEL` names where `--model` is not given
- RULE-27: `record --from` a folder that holds no `reply.md` prints `purlin_ai.py: <folder> holds no reply.md.` on standard error, writes nothing and exits 2
- RULE-28: `grade` asks the model the proof's `@graded(...)` names with the program `run` starts for `--instructions`, the system prompt being the grader's own, in an empty folder outside the project
- RULE-29: The grader's request is `The sentence:`, the proof's sentence as the spec holds it, `The output:`, then `reply.md` and each file under `files/`, each under a line `=== <path> ===`; it holds nothing of `transcript.jsonl` or `purlin.json`
- RULE-30: An answer of one line `accept: <reason>` is printed on standard output and `grade` exits 0; one of `reject: <reason>` is printed and it exits 1; the folder's `purlin.json` gains `grade`, with `model` the grader, `accepted` true or false and `reason`, its other keys left as they were
- RULE-31: A grade changes no file the output's fingerprint is taken over
- RULE-32: A grader that cannot be reached, or whose answer is not one line in either shape, is a grader that gave no answer: `grade` records `accepted` null with the reason, prints `purlin_ai.py: no answer from <grader>: <reason>.` on standard error and nothing on standard output, and exits 2
- RULE-33: Under `PURLIN_AI_REPLAY`, `grade` grades that folder and writes the grade into its `purlin.json`; the folder `PURLIN_AI_OUT` names is left as it was
- RULE-34: `grade` for a proof that names no grader, a proof no spec has, or a folder holding no `reply.md` starts no `claude`, changes no file, names what is wrong and what to do on one line of standard error, and exits 2
- RULE-35: The grader is shown a text over 20,000 characters as its first 10,000 and its last 10,000 around the line `[... <n> characters cut ...]`, a file that is not UTF-8 text as `[not text: <n> bytes]`, and the files after the 50th, in path order, by path alone under `<n> more files, not shown:`
- RULE-36: A session loads the tool servers of the plugin it was given and none of the person's own: it is started without `--strict-mcp-config`, and with `ENABLE_CLAUDEAI_MCP_SERVERS` set to `false`
