# Feature: evidence_writer

> Description: What a run leaves behind. `purlin:test` and `purlin:audit` write this
>   operating system's section of `.purlin/evidence/local/<feature>.json` for every feature
>   they covered, merged into the file already on disk, and render `.purlin/tests.md` from
>   every evidence file. They write and do not commit; `--commit` commits the files under the
>   person's own identity, and nothing ever pushes. Every file is tracked, because the point
>   of them is that somebody who did not make the run can read them.
>   This feature covers the section a run writes, the words a rule reads, the merge, the files
>   a run removes, the table, the lines the run prints, the commit, and the audit's entries.
> Scope: scripts/run/evidence.py, references/formats/evidence_format.md, templates/gitignore.purlin
> Stack: python/stdlib (json, subprocess, datetime), git

## Rules

- RULE-1: A `--test` run writes `.purlin/evidence/local/<feature>.json` for every feature it covered, carrying `schema` `purlin-evidence/1`, the `feature`, the `source` `local` and the `spec` path, and one section keyed by the operating system the run is on, which carries the full `commit` the working tree was on, `dirty`, the `at` time in ISO 8601 UTC, the `runner` slug of the person's email, the `fingerprint` taken over the tree the run saw, a `rules` object and a `proofs` array
- RULE-2: `rules` holds one entry per rule the spec writes, reading `passed` where every proof that could run here passed, `failed` where a test claiming one of them failed, `not run` where a proof is tagged `@env` for another operating system, and `no test` where nothing observed any of them; a rule whose proofs are all `@manual` reads `passed`, because no run was ever going to observe one
- RULE-3: `proofs` holds one entry per proof and test that observed it, each naming its `id`, its `rule`, a `result` of `pass` or `fail`, its `env`, whether it is `manual`, and the `test` as `<file>::<name>`; a proof nothing observed has one entry whose `result` is `missing`, or `not run` when it is tagged for another operating system, and whose `test` is empty
- RULE-4: A run reads the file on disk and replaces only its own operating system's section: a section another operating system wrote and the `audit` object stay byte for byte as they were
- RULE-5: Every write drops the `rules` entries and the `audit.rules` entries of rules the spec no longer carries
- RULE-6: Every run deletes the evidence files under `local/` and `ci/` whose feature no spec defines, and prints `Removed <path>: no spec defines <feature>.` for each
- RULE-7: A run that sees the same thing over the same fingerprint as the section on disk leaves the file byte for byte as it was, `at` and `commit` included, so a second run finds nothing new to commit
- RULE-8: `.purlin/tests.md` is rendered from every evidence file on disk rather than from the run, one row per feature from its newest section in either source, so a `--feature` run leaves every other row as it was; it opens `# Tests at <sha7>`, carries the columns `Feature`, `Rules`, `Passed`, `Failing`, `No test` and `Last run`, counts `No test` as every rule neither passed nor failed, and fills `Last run` with `<sha7> · <at> · <os> · <source>`
- RULE-9: `--test` and `--audit` write the evidence and the table and commit nothing, and print `Evidence written to .purlin/evidence/local/<feature>.json.` when one feature ran and `Evidence written to .purlin/evidence/local/ for <n> features.` when several did
- RULE-10: With `--commit` the run commits the files under `.purlin/evidence/local/`, the table and any file it removed, under the person's own git identity, with the subject `purlin: evidence at <sha7>`, and prints `Evidence committed.`; a run with nothing new prints `Evidence unchanged.` and makes no commit; neither ever pushes or prints a push command
- RULE-11: Outside a git repository the files are still written, and `--commit` says there is no git repository to commit them to
- RULE-12: `--audit` writes one `audit.rules` entry for each rule the AI audit read, carrying the rule, proof and test hashes it read, its `verdict`, its `findings`, `at` and `commit`, and leaves every other rule's entry as it was; it writes `audit.mutation` when mutation testing ran, and null into a file that had no `audit` yet when it did not
- RULE-13: Neither the evidence nor the table is gitignored: `templates/gitignore.purlin` names neither `.purlin/evidence` nor `.purlin/tests.md` as a pattern, and neither does this repository's own `.gitignore`

## Proof

- PROOF-1 (RULE-1): Run `--all --test` over a project with one spec and one tagged passing test; verify `.purlin/evidence/local/feat.json` exists with `schema` `purlin-evidence/1`, `source` `local` and `spec` `specs/a/feat.md`, that its one section is keyed by the operating system the run is on, that the section's `commit` is the 40-character sha HEAD names, its `at` matches `YYYY-MM-DDTHH:MM:SSZ`, its `runner` is `dev`, its `fingerprint` equals the one taken over the project, and that its keys are exactly `commit`, `dirty`, `at`, `runner`, `fingerprint`, `rules` and `proofs`
- PROOF-2 (RULE-2): Call `rule_word()` with one proof observed `pass`; verify `passed`. With one observed `fail` beside one observed `pass`; verify `failed`. With a proof tagged `@env` for another operating system beside a passing one; verify `not run`. With a proof nothing observed; verify `no test`. With no proof at all; verify `no test`. With one proof tagged `@manual`; verify `passed`
- PROOF-3 (RULE-3): Build a section for a spec whose `RULE-1` has `PROOF-1` observed passing by two tests and whose `RULE-2` has an unobserved `PROOF-2`, and a `PROOF-3` tagged for another operating system; verify `PROOF-1` has two entries, one per test, each reading `pass` with its `<file>::<name>`, that `PROOF-2` has one entry reading `missing` with an empty `test`, that `PROOF-3` reads `not run`, and that every entry carries exactly `id`, `rule`, `result`, `env`, `manual` and `test`
- PROOF-4 (RULE-4): Write a file holding a `windows` section and an `audit` object, then write a `linux` section into it; verify the `windows` section and the `audit` object are unchanged and the `linux` section is the one written. Write a second `linux` section observing a failure; verify it replaced the first and the `windows` section is still unchanged
- PROOF-5 (RULE-5): Write a file whose section and `audit.rules` both hold `RULE-1` and `RULE-9`, then write a section for a spec that carries only `RULE-1`; verify `RULE-9` is gone from every section's `rules` and from `audit.rules`
- PROOF-6 (RULE-6): Write evidence for a feature `gone` under both `local/` and `ci/` beside a spec for `feat` only, and run `--all --test`; verify both `gone` files are deleted, `feat` is written, and the output names each removed path with `no spec defines gone`
- PROOF-7 (RULE-7): Run `--all --test` twice in a git checkout with nothing changing between the runs; verify the file's bytes after the second run equal those after the first. Merge a section that differs only in `at`, `commit` and `dirty`; verify the file is unchanged
- PROOF-8 (RULE-8): Render the table from a `ci` file whose `linux` section reads `passed`, `failed` and `not run` for three rules and a `local` file for another feature with one `passed` rule; verify the rows read `3 | 1 | 1 | 1` and `1 | 1 | 0 | 0`, that each `Last run` cell is that feature's `<sha7> · <at> · <os> · <source>`, that the header row names the six columns in order and the file opens `# Tests at `. Give one feature a newer `ci` section and an older `local` one; verify its row is the `ci` one. Run `--feature one --test` then `--feature two --test`; verify the second run left the first row as it was
- PROOF-9 (RULE-9): Run `--all --test` over one spec; verify the output holds `Evidence written to .purlin/evidence/local/feat.json.`, that `git log` shows no new commit and `git status` lists the file as untracked. Run it over two specs; verify `Evidence written to .purlin/evidence/local/ for 2 features.`
- PROOF-10 (RULE-10): In a git checkout run `--all --test --commit`; verify the output holds `Evidence committed.` and no line holding `git push`, that `git log -1 --format=%s` reads `purlin: evidence at <sha7>` for the commit the run started on, that the commit's author is the checkout's own git identity, and that the commit touches `.purlin/evidence/local/feat.json` and `.purlin/tests.md` and nothing else. Run it again; verify `Evidence unchanged.` and that no commit was added
- PROOF-11 (RULE-11): Run `--all --test --commit` in a directory that is not a git repository; verify the evidence file and the table were written and that the output holds `there is no git repository to commit it to`
- PROOF-12 (RULE-12): Merge an audit into a file holding an entry for `RULE-2`, with an entry for `RULE-1` and a mutation of engine `mutmut` and score `71`, mutation having run; verify `audit.rules` holds both entries, `RULE-2` unchanged, and `audit.mutation` reads the new score. Merge again with mutation not run and another mutation handed over; verify `audit.mutation` is unchanged. Merge an audit into a file with no `audit` and mutation not run; verify `audit.mutation` is null. Run `--all --audit` at the gate `strong` over a spec whose `RULE-1` is tagged `[bar: strong]`; verify the file's `audit.rules.RULE-1` carries the payload's `rule_hash`, `proof_hash` and `test_hash` for that rule, the `verdict` `strong`, empty `findings`, an `at` and the `commit`
- PROOF-13 (RULE-13): Read `templates/gitignore.purlin` and this repository's `.gitignore`; verify no line that is not a comment names `.purlin/evidence` or `.purlin/tests.md`
