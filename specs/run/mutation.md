# Feature: mutation

> Description: Test strength is the share of the deliberate breaks made to the code that the
>   tests caught, as an integer percent. Four engines make those breaks, one per language
>   family: Stryker for jest and vitest, Stryker.NET for dotnet, mutmut for pytest, and the
>   empty engine for everything else. Selection reads the config and the detected frameworks
>   alone, so a caller can print the plan before anything runs; the install check happens
>   when the engine runs, and an engine that is not installed answers with the reason in
>   words rather than raising. Every engine answers in one shape, so the evidence carries the
>   same fields whichever one measured it.
> Scope: scripts/run/mutation/__init__.py, scripts/run/mutation/stryker.py, scripts/run/mutation/stryker_net.py, scripts/run/mutation/mutmut.py, scripts/run/mutation/none.py
> Stack: python/stdlib (importlib, subprocess, json, tempfile), Stryker, Stryker.NET, mutmut

## Rules

- RULE-1: With `mutation_engine` set to `auto`, jest and vitest select `stryker`, dotnet selects `stryker_net`, pytest selects `mutmut`, and go, shell and sql select `none`; the first detected framework that has an engine decides, and a project with no framework selects `none`
- RULE-2: A `mutation_engine` naming an engine wins over the detected frameworks, a name outside the four shipped engines reads as `none` rather than being guessed at, and a missing key reads as `none`, so mutation testing is off until a project turns it on
- RULE-3: Test strength is `killed / (killed + survived)` as an integer percent rounded half up, and is None when no break ran at all
- RULE-4: The rules of a feature are reported in rule-number order, so `RULE-2` comes before `RULE-10` [level: passed]
- RULE-5: Stryker runs once per feature against that feature's scope files alone, under a generated config naming `coverageAnalysis: "perTest"`, `disableBail: true`, the `json` reporter and the report path
- RULE-6: The Stryker test runner is `vitest` when the project's `package.json` declares vitest as a dependency, and `jest` otherwise
- RULE-7: The project's own `node_modules/.bin/stryker` is preferred over one on the PATH, and neither present leaves no engine with a line naming the package to install
- RULE-8: A break whose status is `killed` or `timeout` counts caught, one whose status is `survived` or `nocoverage` counts missed, and a break that never reached a test counts for neither
- RULE-9: A rule's number is what its own tests caught: a break only another rule's test caught counts missed for this one, and a rule whose tests the report never lists measures nothing
- RULE-10: A test in the report is matched to a rule's test by its whole name, its titles joined by single spaces whether the name wrote them with ` > ` or not, so a name that begins another is not that test, and never across two files of the same name
- RULE-11: Attribution is `per_test` when any break names the test that caught it and `per_scope` when none does, and every rule then carries the feature's scope number
- RULE-12: A run that wrote no report, or whose report cannot be read, measures nothing for that feature and says so in the log rather than raising
- RULE-13: Stryker.NET is run as `dotnet stryker` with one `--mutate` per scope file, `--coverage-analysis perTest`, `--disable-bail`, `--reporter json` and `--output`, and its report is found by walking that output directory for `mutation-report.json`
- RULE-14: Without `dotnet` on the PATH there is no engine for C#, and with `dotnet` but no Stryker.NET installed the reason names the `dotnet tool install` command; the install check is `dotnet stryker --version` answering 0
- RULE-15: mutmut needs a config block naming the source paths and the test selection, written to `pyproject.toml` as `[tool.mutmut]` when that file exists and to `setup.cfg` as `[mutmut]` with one value a line otherwise; without the block no breaks are made and the reason names the block and the file
- RULE-16: The output of `mutmut results --all true` is read one line per break, and a line whose status is not one mutmut writes is not counted as a break
- RULE-17: A mutmut break is attributed to the scope entry whose last path segments match the most of the break's module name, a break no scope entry covers is left out, and every rule of a feature carries that feature's scope number with `attribution: "per_scope"`
- RULE-18: Without mutmut installed there is no engine and the reason names `pip install mutmut`
- RULE-19: The empty engine measures nothing: every rule carries a score of None and `attribution: "unavailable"`, and the reason is a sentence saying why
- RULE-20: Every engine answers the same shape, so a caller reads one: an engine name outside the four is not run, a rule the engine never reported is filled in with `attribution: "unavailable"`, and a feature the engine never reached is still listed
- RULE-21: A mutmut break in a package's `__init__.py` is attributed to the scope entry naming that `__init__.py`, and a scope entry holding `*` is matched as a glob against the file the break changed, losing to any entry that names the file or its directory
- RULE-22: An engine invocation that runs past `--arm-timeout` measures nothing: every rule it was breaking and that feature's scope score carry a score of None with `attribution: "unavailable"` whatever report it left, mutmut's one run leaving every feature unmeasured and a Stryker or Stryker.NET run leaving only the feature it was breaking, and the answer's reason and log name the seconds and `--arm-timeout`

## Proof

- PROOF-1 (RULE-1): With `mutation_engine` set to `auto`, a project whose one detected framework is jest or vitest gets the engine `stryker`, dotnet gets `stryker_net`, pytest gets `mutmut`, and go, shell or sql gets `none`. With pytest detected before jest the engine is `mutmut`, and with jest before pytest it is `stryker`; with shell detected before dotnet it is `stryker_net`, so a framework with no engine does not decide; with no framework detected it is `none`
- PROOF-2 (RULE-2): With `mutation_engine` set to `mutmut` in a project that detects jest the engine is `mutmut`, and set to `none` in a project that detects pytest it is `none`. Set to `cosmic-ray`, a name no shipped engine has, in a project that detects pytest, it is `none`, not `mutmut`. With the key absent, or no config at all, a pytest or a jest project gets `none`, while the same pytest project with the key at `auto` gets `mutmut`
- PROOF-3 (RULE-3): Test strength for 1 break caught and 1 missed reads 50, 2 caught and 1 missed reads 67, 1 caught and 2 missed reads 33, 5 caught and 2 missed reads 71, 7 caught and 4 missed reads 64, 1 caught and none missed reads 100, and none caught with 1 missed reads 0; with no break caught or missed it reads None, not 0
- PROOF-4 (RULE-4): Call `rules_by_feature()` with the keys `("f", "RULE-10")`, `("f", "RULE-2")` and `("f", "RULE-1")`; verify the list is `["RULE-1", "RULE-2", "RULE-10"]`
- PROOF-5 (RULE-5): The config a feature's run is given, for the scope files `src/calc.js` and `src/util.js` under jest with the report at `/tmp/report.json`, holds exactly those two files to break, `coverageAnalysis` `perTest`, `disableBail` true, the `json` reporter, the runner `jest` and that report path, and nothing more. A run of the feature `calc`, scoped to `src/calc.js`, in which Stryker writes a captured report where the config says, starts `stryker run` with a config that breaks `src/calc.js` alone, and answers engine `stryker`, available, with the feature's scope score 64 and its RULE-2 at 71, both read from that report, and a log naming `calc`
- PROOF-6 (RULE-6): A project whose `package.json` lists vitest under `devDependencies` runs Stryker with the runner `vitest`; a project whose `package.json` lists only jest, and one with no `package.json` at all, run it with `jest`
- PROOF-7 (RULE-7): With a `stryker` in the project's `node_modules/.bin/` and another on the PATH, the project's own is the one run; with neither present, a run answers engine `none`, not available, with a reason reading `stryker is not installed`, and the feature's rule at score None with `attribution: "unavailable"`
- PROOF-8 (RULE-8): A Stryker report of 12 breaks to one file, 6 `Killed`, 1 `Timeout`, 2 `Survived`, 2 `NoCoverage` and 1 `CompileError`, gives the feature a scope score of 7 caught and 4 missed, 64; the `CompileError` break counts for neither, so 11 of the 12 are counted
- PROOF-9 (RULE-9): Of a report's 7 caught breaks, the rule whose test is `adds two numbers` is credited the 3 that test caught and reads 100 with none missed, and the rule whose test is `leaves small values alone` is credited the 5 its test caught with the 2 its test reached and nothing caught counted missed, reading 71, both with `attribution: "per_test"`, so a break only the other rule's test caught is not counted caught for either. A rule whose one test, `unrelated`, the report never lists reads score None with 0 caught and 0 missed
- PROOF-10 (RULE-10): A report lists the tests `locks` and `locks after five` in one file; `locks` caught one break, and `locks after five` reached another that nothing caught. The rule whose test is `locks` reads 1 caught and 0 missed and the rule whose test is `locks after five` reads 0 caught and 1 missed, so the shorter name does not claim the longer one's break. A report whose test `locks the account` in `test/other.test.js` caught a break credits nothing to a rule whose test of that name is in `test/login.test.js`: the rule reads 0 caught
- PROOF-11 (RULE-11): A Stryker.NET report of breaks to `src/Login/Session.cs` in which no break names the test that caught it, 3 caught and 2 missed, gives the feature 60 and gives both its rules 60, 3 caught and 2 missed, with `attribution: "per_scope"`, and a Stryker.NET run over that file prints `attribution per_scope` in its log. A report in which the breaks do name the test that caught them, read as Stryker.NET, gives the rule `attribution: "per_test"`
- PROOF-12 (RULE-12): A report file holding the text `not json`, and a report path where no file exists, each read as no report rather than an error. A Stryker run that exits 1, prints `boom` and writes no report answers with the feature's rule at score None and a log that says `wrote no report` and carries `boom`; a feature with no scope files is not broken, reads score None for the feature and for its rule, and the log says `no scope files`
- PROOF-13 (RULE-13): A Stryker.NET run of a feature scoped to `src/Login/Session.cs` and `src/Api.cs`, with the output directory `/tmp/out`, is exactly the command `dotnet stryker --mutate src/Login/Session.cs --mutate src/Api.cs --coverage-analysis perTest --disable-bail --reporter json --output /tmp/out`. A `mutation-report.json` in a `reports` folder under the output directory is the report found, and an output directory holding no report gives none
- PROOF-14 (RULE-14): With no `dotnet` on the PATH, Stryker.NET is not available and the reason reads `dotnet is not installed`, and a run answers engine `none` with that reason. With a `dotnet` whose `dotnet stryker --version` exits 1, it is not available and the reason names `dotnet tool install -g dotnet-stryker`; when that command exits 0, it is available with an empty reason, and `dotnet stryker --version` is the command the check ran
- PROOF-15 (RULE-15): The block for a project with a `pyproject.toml`, for the source path `src` and the tests `tests`, is exactly the three lines `[tool.mutmut]`, `source_paths = ["src"]` and `pytest_add_cli_args_test_selection = ["tests"]`. A project with no `pyproject.toml` gets its block in `setup.cfg`, and for `src`, `lib`, `tests` and `-q` it reads `[mutmut]`, `source_paths =`, then `src` and `lib` each on its own indented line, `pytest_add_cli_args_test_selection =`, then `tests` and `-q` the same way. A `pyproject.toml` without the block does not count as holding it, and does once the block is added. With mutmut installed and a `pyproject.toml` that has no block, a run never starts mutmut and answers engine `none` with a reason naming `[tool.mutmut]` and `pyproject.toml`
- PROOF-16 (RULE-16): The listing a real mutmut 3.8 run printed for `mutmut results --all true`, five lines, reads as 5 breaks, the first `calc.ops.x_add__mutmut_1` with the status `killed`, and 1 of the 5 caught. A listing holding the lines `2 files mutated, 0 ignored, 0 unmodified`, `244.79 mutations/second`, `login.session.x_lock_account__mutmut_1: killed` and `Error: something else entirely` reads as exactly one break, `login.session.x_lock_account__mutmut_1` `killed`: the `Error` line is not counted as a break
- PROOF-17 (RULE-17): With the scope entries `src` and `src/login/session.py`, the break `login.session.x_lock__mutmut_1` belongs to `src/login/session.py`, the entry matching more of its name; `calc.ops.x_add__mutmut_1` belongs to the entry `calc`, and `other.thing.x_go__mutmut_1` to no entry when the scope is `src/login/session.py`. A mutmut listing of nine breaks gives `src/login/session.py` 4 caught and 2 missed and `src/reports/render.py` 0 caught and 1 missed, and leaves out the break in `unrelated.tool`, which no scope entry covers. A run over the features `login` and `reports` runs `mutmut run` and then `mutmut results --all true`, and gives both rules of `login` 67, 4 caught and 2 missed, with `attribution: "per_scope"`, and the rule of `reports` 0
- PROOF-18 (RULE-18): With mutmut not installed, a run over the feature `login` answers engine `none` with a reason naming `pip install mutmut`, and the feature's rule reads `attribution: "unavailable"`
- PROOF-19 (RULE-19): The empty engine, asked about the feature `deploy`, scoped to `deploy.sh`, with one rule, answers engine `none`, not available, with a reason naming `shell or sql`, the feature's scope score at None with 0 caught and 0 missed, and the rule at `attribution: "unavailable"`
- PROOF-20 (RULE-20): Asked to run the engine `none`, the engine `mutmut` over a project with its block, and the engine `cosmic-ray`, each answer carries exactly `engine`, `available`, `reason`, `features` and `log`, lists every feature asked about, and gives each feature a scope score of exactly `score`, `killed` and `survived` and each rule exactly `engine`, `score`, `killed`, `survived` and `attribution`, the last one of `per_test`, `per_scope` and `unavailable`; the `mutmut` answer gives RULE-1 67, and `cosmic-ray` answers engine `none` with a reason naming `unknown engine`. An engine that reports the feature `calc` at 3 caught and 1 missed and neither of its two rules leaves `calc` at 75 and fills RULE-1 in with score None and `attribution: "unavailable"`; an engine that reports no feature still lists `login` and `reports`, the two asked about
- PROOF-21 (RULE-21): With the scope entries `scripts/run/mutation/__init__.py` and `scripts/run/mutation/mutmut.py`, the break `scripts.run.mutation.x_score_percent__mutmut_1` belongs to `scripts/run/mutation/__init__.py` and `scripts.run.mutation.mutmut.x_binary__mutmut_2` to `scripts/run/mutation/mutmut.py`. With the one scope entry `scripts/**/*.py`, the breaks `scripts.run.host.x_commit__mutmut_1` and `scripts.mcp.purlin.x_read__mutmut_1` belong to the glob and `dev.build_report.x_build__mutmut_1` to no entry; with `scripts/run/host.py` added beside the glob, the break in `scripts.run.host` belongs to `scripts/run/host.py`
- PROOF-22 (RULE-22): With the limit at 90 seconds, a mutmut run over `login` and `reports` whose `mutmut run` is stopped at the limit, beside a results listing that would give `login` 67, answers engine `mutmut`, available, both features' scope scores at None and all three rules at score None, 0 caught and 0 missed with `attribution: "unavailable"`, and its reason and its log each carry `timed out after 90 s` and `--arm-timeout`. A Stryker run whose features `calc` and `slow` both leave a report, with only `slow` stopped at the limit, gives `calc` its 64 and `slow` a scope score of None and its rule None with `attribution: "unavailable"`; a Stryker.NET run does the same, `login` keeping 60 and `slow` unmeasured, and each names `timed out after 90 s` and `--arm-timeout` in its reason and its log
