# Feature: run_script

> Description: The one command that runs a project's tests and writes what they saw.
>   `purlin:test` runs it as `--test`, `purlin:audit` as `--audit`, and the CI job as
>   `--ci`. It resolves the configuration and the suites the settings name, scans the specs
>   and the markers, runs each suite's own command, ties each result in its report to the
>   markers above its test, and then checks the two things no test framework reports on its
>   own: a suite that left no report, and a marker of a feature it covers that has no result.
>   It hands what it saw to the evidence writer, whose own spec covers the file. How a report
>   is read and a result tied to its marker is the `reports` spec.
> Scope: scripts/run/purlin_run.py
> Stack: python/stdlib (subprocess, re, hashlib), bash, pytest, sqlite3

## Rules

- RULE-1: The command line names exactly one of `--test`, `--audit` and `--ci`, and at most one of `--all` and `--feature`; `--remote` belongs to `--test`, and `--commit` belongs to `--test` and `--audit` without `--remote`. Any other shape exits 2 and prints the usage line, and `--audit --remote` exits 2 naming `purlin:test --remote`
- RULE-2: A `--feature` name with no spec under `specs/` exits 2 naming it, and a `--project-root` that is not a directory exits 2 saying so
- RULE-3: `--test` runs each suite the `tests` setting names and writes what they saw into `.purlin/evidence/local/<feature>.json`; nothing is written under `specs/`
- RULE-4: A SQL script in an `exit` suite run through `sqlite3 -bail` is one test: it passes when every statement succeeds and fails when one raises an error
- RULE-5: A test that fails exits the run 1 and its proof reads `fail` in the evidence; a failing test is a result, so the run does not call it missing evidence
- RULE-7: A project whose tests carry no marker is not missing evidence: the run names nothing missing, and the table is what says a rule has no test
- RULE-8: A marker of a feature the run covers whose test has no passing or failing result, because it was skipped, the report does not hold it, or no test follows the marker, exits the run 1 and is named with its file and line; at most 5 are listed and the rest are counted
- RULE-9: A marker naming a feature this run did not select is not reported as missing
- RULE-10: A proof the spec tags `@env` for another operating system is not counted here and is never reported missing; the run prints one sentence for it, `<feature> PROOF-N needs <os>; this machine is <os>. A remote runner runs it: purlin:init adds one.`, and a proof tagged for this one is counted like any other
- RULE-11: Every run ends on the status table, then the summary sentence and `Left to do`, which count every rule under `specs/` rather than only the features it ran; the run exits on the tests alone: 1 where a test failed, evidence is missing or a marker names nothing a spec has, 0 otherwise. A project with no specs says so and exits 1 [level: passed]
- RULE-12: `--ci` on a run branch writes this runner's section of `.purlin/evidence/ci/<feature>.json` for every feature it covered, with the runner `ci`, and hands every path to the git host's commit with the subject `purlin: evidence at <sha7>` and the merge that puts its section into what the branch holds, at every gate, then prints `Evidence committed.`
- RULE-15: `--audit` and `--ci` write the run's console log to `.purlin/runtime/run.log`
- RULE-16: The breaks are asked for each feature's scope files and the tests of each rule
- RULE-17: `--test` and `--audit` never commit through the git host's API, even with `--commit`, and write nothing under `.purlin/evidence/ci/`; only `--ci` commits through the API; no run of any kind writes a signature file
- RULE-47: A `--ci` run writes only where the evidence it writes is kept, which is a `run/*` branch. On a tag run it writes nothing at all and prints `Tag run: nothing is written.`, because what a tag run is for is the rerun and the gate check over the evidence already committed
- RULE-20: The evidence a run wrote makes a rule's passed cell read `passed` while its fingerprint is the one taken now, committed or not; changing a scoped file makes the cell read `out of date` with the reason `code changed since <sha7>`, editing the spec `spec changed since <sha7>`, and editing a test file `tests changed since <sha7>`, where the sha is the commit the run started on; the next run clears it
- RULE-21: The operating system this run is on is reported as `windows`, `macos` or `linux` and never as anything else
- RULE-22: The run script's source carries no emoji [level: passed]
- RULE-39: The run script reconfigures stdout and stderr to UTF-8 before it prints anything, so a console whose codec is cp1252 prints the state table's glyphs instead of ending the run with an encoding error
- RULE-40: A suite that exits non-zero or is killed has the last 60 lines of its own output printed to stdout under `--- <suite> output (last 60 lines) ---` before the status table, and `--audit` and `--ci` keep the whole of every suite's output in `.purlin/runtime/run.log`
- RULE-41: `--project-root` with an empty value exits 2 naming the flag, rather than resolving to the working directory and running there
- RULE-43: No marker is read from `mutants/`, the copy mutmut leaves of the project, so a test mutmut copied is never counted twice
- RULE-45: Mutation testing decides the breaks and only `--audit` ever runs them: under the gate `passed` an `--audit` run makes none and leaves `audit.mutation` null; with `mutation_engine` `none` it makes none, and a rule the AI audit found nothing against reads `strong` with the reason `no mutation score measured`; otherwise the breaks run for each feature with a rule the audit reads and for no other, the score lands in `audit.mutation`, and a score under `min_strength` leaves the strong cell `weak`; a `--ci` run makes no breaks, calls no model and writes no `audit` at any gate
- RULE-48: Above the gate `passed`, `--audit` exits 1 when a rule under `specs/` is short of its passed cell or, where its level asks for one, its strong cell, so a finding blocks, and a rule waiting only on a signature does not make it exit 1; at the gate `passed` nothing the audit found makes it exit 1
- RULE-49: `--audit` reads each rule of the features it runs that is the feature's own, has a proof with a test, whose passed cell reads `passed` and that has no audit entry for its current rule, proof and test; above the gate `passed` it never reads a rule whose level is `passed`, and at the gate `passed` it reads every such rule. With no feature named and no `--all` it reads the rules of every feature, whichever features its tests ran, and `--all` reads every such rule again whatever entry it has
- RULE-50: Before its first model call `--audit` prints `AI audit: <n> rules to read, <k> at a time.`, where `<k>` is the lower of `audit_parallel` and `<n>`, and carries on without asking; with nothing to read it prints `AI audit: nothing to read; every rule matches its last audit.` and calls nothing
- RULE-51: `--audit` makes one model call per rule it reads, `audit_parallel` of them at once, 4 when the setting is absent and 4 with one warning when it is not a whole number from 1 to 16, and writes each answer into that rule's `audit.rules` entry in `.purlin/evidence/local/<feature>.json` with its `verdict`, its `findings`, the `model` that answered and the sha256 of the `criteria` it was sent
- RULE-52: A rule the model could not be reached for gets nothing written into the evidence, its strong cell reads `not audited` with the reason `the AI audit could not run: <why>`, the run prints one line per cause with its count, `<n> rules could not be audited: <why>.` followed by what to do, and above the gate `passed` it exits 1; the next audit reads the rule again
- RULE-53: When a fresh audit changes what the audit found for a rule whose signature was current, the run prints `<n> signatures went stale: their audit findings changed.`, and the rule's signed cell reads `stale` with the reason `audit findings changed after the signature`; an audit that finds the same stales nothing
- RULE-55: With no feature named and no `--all`, `--test` and `--audit` run a feature when no section for this operating system exists in either source of its evidence, when the newest such section's fingerprint differs from the one taken now on its spec, its code or its tests, when an untracked file git does not ignore sits under its `> Scope:` or beside one of its marker files, or when its spec names no files; an anchor's rules count in the spec of every feature that requires it, so an anchor edit runs those features; every other feature is not run and its evidence is left as it was
- RULE-56: Before it runs anything, such a run prints `Selected <n> of <m> features: <feature> (<reasons>), ...` with the reasons `no run on <os> yet`, `<part> changed since <sha7>`, `a file is not tracked` and `names no files, so every run includes it`, then `Skipped <k> features whose spec, code and tests match their evidence: <names>. purlin:test --all runs them too.`, naming ten and counting the rest, then one line for each untracked file that selected a feature, `<path> is under <feature>'s scope and is not tracked, so its content is not part of the evidence until you git add it.`
- RULE-57: When such a run selects nothing it prints `Nothing to run: every feature's spec, code and tests match its evidence. purlin:test --all runs them anyway.`, runs no test, writes no evidence, ends on the status table, the summary sentence and `Left to do`, and exits 1 where a rule's tests fail in the evidence it stands on and 0 otherwise; with `--commit` it still commits the evidence an earlier run wrote
- RULE-58: A run over fewer features than the project has gives each suite's `{files}` only the test files that carry a marker of a feature it runs, and starts no suite that has none; a run over every feature runs every suite whole
- RULE-59: `--all` runs every feature whatever its evidence says, and `--ci` with no feature named runs every feature
- RULE-60: With no feature named, `--audit` runs its tests on the selection RULE-55 makes and then reads the rules RULE-49 names; with nothing selected it runs no test and still reads each rule that has no audit entry for its current text, proof and test
- RULE-54: `--audit` keeps one line before its ending: after the lines naming the evidence it wrote and committed, it prints `AI audit: <n> rules read, <s> strong, <w> weak.` with the rules it skipped, then one line per cause the model could not be reached, then the status table, the summary sentence and `Left to do`
