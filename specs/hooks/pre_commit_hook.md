# Feature: pre_commit_hook

> Requires: security_no_dangerous_patterns
> Scope: scripts/hooks/pre-commit.sh
> Stack: shell/bash, python3 (config parsing, purlin_server.generate_digest)
> Description: Pre-commit git hook that keeps `.purlin/report-data.js` in step with the commit that is being made. Three modes read from `digest` in `.purlin/config.json`: auto (default) regenerates the digest and stages it, warn only reports a missing or stale digest, off does nothing. The hook never blocks a commit, so every path that gives up has to say so out loud: a silent skip reads exactly like a hook that worked.

## Rules

- RULE-1: The hook exits 0 on every path, so it can never block a commit. `PURLIN_SKIP_DIGEST=1` skips everything before the project root or the config is read and prints exactly one line naming the variable; mode `off` prints exactly one line naming the mode and reads no digest file. Neither path writes or stages `.purlin/report-data.js`
- RULE-2: The Purlin plugin root is resolved in the same order as pre_push_hook RULE-14: the directory this script lives in (resolved through `readlink` for a symlinked install), `$PURLIN_PLUGIN_ROOT`, `$CLAUDE_PLUGIN_ROOT`, then the project root for a dev checkout of the framework. The first candidate carrying `scripts/mcp/purlin_server.py` wins, and a candidate that does not carry it is stepped over rather than ending the search. When no candidate carries it, auto mode prints a WARNING naming every path searched and exits 0, never a silent skip
- RULE-3: A directory with no `.purlin/` is not a Purlin project: the hook exits 0 with no output, the twin of pre_push_hook RULE-3. When `.purlin/config.json` cannot be parsed, or its `digest` value is not one of `auto`, `warn` and `off`, the hook prints one line naming the config file and the value it got, states that `auto` is assumed, and then runs auto
- RULE-4: In auto mode the hook regenerates the digest through `purlin_server.generate_digest` and stages exactly the one file it returns with `git add`, printing the staged path, so a commit made through the hook carries a current `.purlin/report-data.js`. The server directory and the project root reach python as argv, never spliced into the python source, so a path containing a quote cannot rewrite the program. When `generate_digest` raises, the python error text reaches the developer (its stderr is not captured and not redirected), the hook prints that generation failed and that the commit continues, and the digest on disk is left as it was
- RULE-5: In warn mode the hook never regenerates and never stages: it prints a WARNING when `.purlin/report-data.js` is missing, a WARNING naming 3600 seconds when the file's `timestamp` is older than that, and nothing at all when the timestamp is fresh
- RULE-6: No command in the hook has its stderr redirected to `/dev/null`: `scripts/hooks/pre-commit.sh` contains zero occurrences of `2>/dev/null`, so a traceback out of `generate_digest` reaches the developer running `git commit` instead of being swallowed

## Proof

- PROOF-1 (RULE-1): Create a temp git project with `{"digest": "auto"}` and no `.purlin/report-data.js`; run pre-commit.sh with `PURLIN_SKIP_DIGEST=1`; verify exit 0, exactly 1 non-empty output line containing `PURLIN_SKIP_DIGEST`, that `.purlin/report-data.js` does not exist, and that `git diff --cached --name-only` is empty @integration
- PROOF-2 (RULE-1): Set `{"digest": "off"}` in the same project; run pre-commit.sh; verify exit 0, exactly 1 non-empty output line containing `"off"`, that `.purlin/report-data.js` does not exist, and that `git diff --cached --name-only` is empty @integration
- PROOF-3 (RULE-2): Copy pre-commit.sh to `<tmp>/copy/scripts/hooks/pre-commit.sh` so its own-directory candidate carries no server, set `PURLIN_PLUGIN_ROOT` to an empty directory and `CLAUDE_PLUGIN_ROOT` to the plugin checkout, and run it in a project carrying no `scripts/mcp/`; verify exit 0 and that `git diff --cached --name-only` lists `.purlin/report-data.js`, so the empty second candidate was stepped over rather than ending the search @integration
- PROOF-4 (RULE-2): Run that same copied hook with `PURLIN_PLUGIN_ROOT` set to an empty directory and `CLAUDE_PLUGIN_ROOT` removed from the environment, in a project carrying no `scripts/mcp/`; verify exit 0, output containing `WARNING`, `scripts/mcp/purlin_server.py` and all 3 searched paths (the copy root, the empty directory, the project root), and that `git diff --cached --name-only` is empty @integration
- PROOF-5 (RULE-3): Run pre-commit.sh three times: in a git repo with no `.purlin/` directory verify exit 0 and zero bytes of output; then with `.purlin/config.json` set to `{"digest": 7}` verify exit 0, output naming the config path and `assuming "auto"`, and `.purlin/report-data.js` listed by `git diff --cached --name-only`; then with the file truncated to `{"digest":` verify exit 0 and the same `assuming "auto"` line naming the path @integration
- PROOF-6 (RULE-4): Run pre-commit.sh in auto mode with `PURLIN_PLUGIN_ROOT` at the plugin checkout; verify exit 0, output containing `digest updated and staged: .purlin/report-data.js`, that `git diff --cached --name-only` lists exactly the 1 path `.purlin/report-data.js`, and that the file starts with `const PURLIN_DATA = `; then replace `specs/hooks/sample_feature.md` with a directory of that name so `generate_digest` raises, run again, and verify exit 0, output containing `digest generation failed`, and the staged digest byte-identical to the one from the first run @integration
- PROOF-7 (RULE-5): Set `{"digest": "warn"}` and run pre-commit.sh three times: with no `.purlin/report-data.js` verify exit 0 and `WARNING` with `not found` in the output; with a digest whose `timestamp` is 7200 seconds old verify exit 0 and `WARNING` with `3600` in the output; with the timestamp set to now verify exit 0 and zero non-empty output lines. After all 3 runs verify `git diff --cached --name-only` is empty and the digest file's bytes are unchanged @integration
- PROOF-8 (RULE-6): Replace `specs/hooks/sample_feature.md` with a directory of that name so `generate_digest` raises, run pre-commit.sh in auto mode, and verify the caller receives `IsADirectoryError` and the string `sample_feature.md` in the hook's stderr; then read `scripts/hooks/pre-commit.sh` and verify it contains zero occurrences of `2>/dev/null` @integration
