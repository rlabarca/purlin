# Feature: refresh_digest_hook

> Requires: security_no_dangerous_patterns
> Scope: scripts/hooks/refresh_digest.py, hooks/hooks.json
> Stack: python3 (stdlib only before the dirty check; purlin_server.generate_digest after it), Claude Code plugin hooks
> Description: The Claude Code plugin hook that keeps `.purlin/report-data.js` current while agents work, so the dashboard shows the state of the project's specs, proofs, receipts and gauges without anyone calling `purlin:status`. Registered as an async `PostToolUse`, `SubagentStop` and `Stop` hook, it runs in the background after a tool call or a turn, decides from file mtimes whether anything the digest reports has changed, and regenerates only then. It never blocks, never prints, never reaches the network and never runs an audit. `hooks/hooks.json` is in scope because the registration is the behaviour: which events fire it, that every entry is async, and that nothing in the file can gate a tool call.

## Rules

- RULE-1: The hook exits 0 on every path and writes nothing to stdout or stderr on any path, including a project that is not a git repository, a project with `report` false, a held lock, an exception inside generation and `PURLIN_SKIP_DIGEST=1`. A refresh that did not happen is a stale dashboard, never a blocked tool call, and an async hook's output is discarded by the harness while a synchronous one's would land in the transcript, so silence is the only output that costs nothing under both
- RULE-2: The hook regenerates only when an input is newer than the digest: the spec directory's `*.md`, `*.proofs-*.json` and `*.receipt.json` files, every `*.json` under `.purlin/cache/`, and `.purlin/config.json`, compared by mtime against `.purlin/report-data.js`, with a missing digest counting as dirty. The digest itself and everything under `.purlin/runtime/` are not inputs, so a run can never make the next run dirty. The check runs before any Purlin module is imported, so a tool call that changed nothing costs a process start and a directory walk
- RULE-3: One generation at a time. The hook takes a non-blocking exclusive lock on `.purlin/runtime/refresh_digest.lock` and leaves at once when another instance holds it, because the holder re-checks the inputs after writing (RULE-4) and so picks up what landed meanwhile. The lock dies with its process, so a killed instance leaves nothing to clean up
- RULE-4: After writing, the hook checks the inputs again against the moment it started generating, and regenerates when something landed during the build, at most three times in one run. A write that lands between the last check and the lock's release is picked up by the next event, which is why the hook is registered on `Stop` and `SubagentStop` as well as `PostToolUse`
- RULE-5: The hook leaves without generating when `.purlin/config.json` is missing or unreadable, when its `report` is not true, when its `digest` is `off`, when `PURLIN_SKIP_DIGEST` is `1`, or when the repository's `index.lock` exists, because a commit is in flight and the pre-commit hook owns that regeneration. The hook's stdin is drained and never parsed: which tool ran does not change whether the digest is stale
- RULE-6: The hook generates through `purlin_server.generate_digest` with `generated_by='hook'`, `network=False` and `only_if_changed=True`, so the digest names its producer, no `git ls-remote` runs from a background hook, and a build whose payload matches the file on disk touches the file instead of rewriting it, leaving the working tree as it was
- RULE-7: `hooks/hooks.json` registers this script and nothing else, under exactly the events `PostToolUse` (matcher `Bash|Write|Edit|MultiEdit`), `SubagentStop` and `Stop`, every entry `type: command` with `async: true` and a `timeout`, and its command invoking `scripts/hooks/refresh_digest.py` under `${CLAUDE_PLUGIN_ROOT}`. No `PreToolUse`, `PermissionRequest` or `UserPromptSubmit` entry exists: those are the events through which a hook can gate or steer a turn, and `references/hard_gates.md` promises that no Claude Code hook does

## Proof

- PROOF-1 (RULE-1): Run `scripts/hooks/refresh_digest.py` as a subprocess with a hook-shaped JSON on stdin in five settings: a temp git project with `report` true and no digest; a temp directory that is not a git repository; the project with `report` false; the project with the lock already held by the test; and the project with `PURLIN_SKIP_DIGEST=1`. Verify every run exits 0 with zero bytes on stdout and zero bytes on stderr, and that only the first produces `.purlin/report-data.js` @integration
- PROOF-2 (RULE-2): In a temp git project run the hook and record the digest's bytes and mtime; run it again with nothing changed and verify both are identical; create a file under `.purlin/runtime/` newer than the digest and run again, verify both are still identical; append a second proof entry to the feature's proof file and run again, verify the digest's `features[0].proved` rose from 1 to 2; then touch `.purlin/config.json` and run, verify the mtime advanced @integration
- PROOF-3 (RULE-3): Make the project dirty, hold `.purlin/runtime/refresh_digest.lock` from the test through `static_checks._lock_exclusive`, run the hook as a subprocess and verify exit 0 with no output and no `.purlin/report-data.js`; release the lock, run again and verify the digest appears @integration
- PROOF-4 (RULE-4): Import the script as a module and call `main()` in a dirty temp project with `purlin_server.generate_digest` replaced by a wrapper that, on its first call only, appends a proof entry to the proof file after delegating to the real function; verify the wrapper ran exactly twice and the digest on disk carries the appended proof. Replace it with a wrapper that always appends and verify it ran exactly three times @integration
- PROOF-5 (RULE-5): Run the hook in a dirty temp git project under each of: no `.purlin/config.json`; a config whose `report` is false; a config whose `digest` is `off`; `PURLIN_SKIP_DIGEST=1`; and an `index.lock` file present under the git directory. Verify no `.purlin/report-data.js` is written in any of them and every run exits 0 silently; remove the `index.lock` and verify the digest is written @integration
- PROOF-6 (RULE-6): Declare an anchor with a git `Source` and a pin in a dirty temp project, call `main()` in-process with `purlin_server.subprocess.run` wrapped to record every argv, and verify no recorded argv contains `ls-remote`, that the digest's `generated_by` is `hook` and the anchor's `ext_status` is `unchecked`; then run `main()` again with the inputs unchanged but the digest's mtime set into the past and verify the file's bytes are unchanged while its mtime advanced, so an unchanged payload was touched rather than rewritten @integration
- PROOF-7 (RULE-7): Parse `hooks/hooks.json` and verify its event keys are exactly `PostToolUse`, `SubagentStop` and `Stop`, that the `PostToolUse` matcher is `Bash|Write|Edit|MultiEdit`, that every entry across all three is `type` `command` with `async` true and an integer `timeout`, and that every command names `scripts/hooks/refresh_digest.py` and `${CLAUDE_PLUGIN_ROOT}`; verify no key named `PreToolUse`, `PermissionRequest` or `UserPromptSubmit` exists @unit
