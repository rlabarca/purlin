# Feature: qa_report

> Scope: tools/QA/purlin-qa-report.md, tools/QA/purlin-qa-report.skill, tools/PM/purlin-anchor-userstories.md, tools/PM/purlin-anchor-userstories.skill
> Stack: markdown (packaged Claude skill)
> Description: The `purlin-qa-report` skill under `tools/QA/`: how a QA reader fetches a project digest without putting a credential anywhere it can leak, which digest fields the report must read and repeat, and what it is forbidden to claim on the strength of them. The `.skill` files under `tools/` are zip archives of these same markdown files, so the rules that cover the text cover what ships.

## Rules

- RULE-1: FORBIDDEN: no instruction in `tools/QA/purlin-qa-report.md` puts a credential in a URL. No `://user:secret@host` form appears anywhere in the file, placeholder or literal, and the clone instructions reach a private repository through `gh repo clone` or through a configured git credential helper instead. A credential written into a URL lands in shell history, in the clone's own config, and in the process table, so a skill that teaches the form teaches the leak
- RULE-2: The skill reads and reports these digest fields by name: `audit_summary.coverage` as `measured` of `total`, `assessed` and `weighted` as two separate numbers that are never substituted for one another, `audit_summary.auditors` when the digest carries it, each feature's `vhash`, `receipt.vhash_version`, `receipt.test_run_commit` and `evidence_stale`, and the top level `git_sha`. `auditors` and `evidence_stale` are read defensively, because a digest written before those fields existed omits them and a report that prints `false` for an absent `evidence_stale` states a fact the digest never recorded
- RULE-3: The skill describes VERIFIED as "all rules proved on every declared platform and a receipt matches". The older wording ran the three conditions together as a list, which let a reader take VERIFIED for an approval rather than for the state of the evidence
- RULE-4: The skill reports `uncommitted` whenever it is non-empty and names all three ways a committed digest can carry one: the `digest` config set to `warn` or `off`, a commit made with `PURLIN_SKIP_DIGEST=1`, and the pre-commit hook taking one of its fail-open paths. The instruction to ignore the field is gone: it rested on the claim that the hook makes a non-empty `uncommitted` impossible, and each of the three routes is a counterexample
- RULE-5: FORBIDDEN: the skill never tells the report to state a human judgment. The strings `signed off`, `sign off` and `compliance status` are absent from the file, and its rules list forbids declaring a project compliant, approved, cleared or certified. No digest field records a person accepting a result, so a report that states one is reporting something it did not read
- RULE-6: Every `.skill` archive under `tools/` holds exactly one `SKILL.md` whose bytes equal the sibling `.md` file, for both `tools/QA/purlin-qa-report` and `tools/PM/purlin-anchor-userstories`. The `.md` is what a reviewer reads and the `.skill` is what a user installs, so a zip regenerated from an older `.md` ships instructions the repository no longer contains. `dev/pack_tools.sh` regenerates both archives from the markdown

## Proof

- PROOF-1 (RULE-1): Read `tools/QA/purlin-qa-report.md` and search it for a credential-bearing URL with two patterns: the placeholder form `://<[A-Z_]+>:<[A-Z_]+>@` and the general form `://[^/\s]+:[^/\s]+@`. Assert both find zero matches. Then assert the file contains `gh repo clone` and the words `credential helper`, so the proof cannot pass on a file that dropped the private-repo path altogether. Putting the literal `https://<USERNAME>:<TOKEN>@` back fails the first pattern
- PROOF-2 (RULE-2): Read `tools/QA/purlin-qa-report.md` and assert each field name appears at least once, one assertion per field so the failure names the missing one: `audit_summary.coverage`, `measured`, `total`, `assessed`, `weighted`, `auditors`, `vhash`, `receipt.vhash_version`, `receipt.test_run_commit`, `evidence_stale`, `git_sha`. Assert `assessed` and `weighted` occur in one sentence together with the word `separately`, so the two scores cannot be reported as one, and that `auditors` and `evidence_stale` each occur within 300 characters of the word `defensively`. Deleting the `evidence_stale` bullet fails the proof
- PROOF-3 (RULE-3): Assert the exact sentence `all rules proved on every declared platform and a receipt matches` appears in `tools/QA/purlin-qa-report.md`, and that the retired wording `every rule proved, receipt current, and every declared platform proved` does not. Restoring the retired wording fails the proof
- PROOF-4 (RULE-4): Locate the `uncommitted` paragraph in `tools/QA/purlin-qa-report.md` and assert it contains all three causes: `warn`, `off`, `PURLIN_SKIP_DIGEST=1` and `fail-open`. Assert the retired sentence `ignore it` is absent from that paragraph and that the word `non-empty` appears in it. Reverting the paragraph to the one-line note that told the reader to ignore the field fails the proof
- PROOF-5 (RULE-5): Lowercase `tools/QA/purlin-qa-report.md` and assert zero occurrences of `signed off`, `sign off`, `signed-off`, `sign-off` and `compliance status`. Assert the numbered rules list carries a rule naming `compliant`, `approved`, `cleared` and `certified` as words the report never uses, so removing the prohibition fails even if the forbidden strings stay absent. Putting `(signed off)` back into any line fails the proof
- PROOF-6 (RULE-6): For each of `tools/QA/purlin-qa-report` and `tools/PM/purlin-anchor-userstories`, open the `.skill` file as a zip, assert its namelist is exactly one entry ending `/SKILL.md`, read that entry's bytes and assert they equal the bytes of the sibling `.md` file. Assert both archives were found, so the loop cannot pass over an empty list. Appending a byte to either `.md` without rerunning `dev/pack_tools.sh` fails the proof
