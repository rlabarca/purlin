# Feature: model_routing

> Description: Which model each Purlin skill runs on. Every skill names its tier in its own front
>   matter and a project gives each tier a model in `.purlin/routing.json`. A command the person
>   types runs on its model through a project skill `purlin:route on` writes: Claude Code
>   switches the session's model for it, or, for a skill that asks the person questions, the
>   project skill hands it to a `purlin:runner` subagent on that model and sends every answer to
>   that same subagent. A skill another skill runs takes the model already running. The audit's
>   planted bugs are written on the `performance` model. `references/formats/routing_format.md` is
>   the one home of all of it.
> Scope: references/formats/routing_format.md, skills/, agents/purlin.md, agents/runner.md
> Stack: markdown, Claude Code skill and agent definitions
> Highest-Rule: 11
> Highest-Proof: 17

## Rules

- RULE-1: Each skill but `route` names one tier in its front matter, `tier: fast`, `tier: balanced` or `tier: performance`, the tier the format's table gives it, and `route` names none
- RULE-2: The format gives each tier its default model: `fast` is `haiku`, `balanced` is `sonnet` and `performance` is `opus`
- RULE-3: The format gives the two project skills `purlin:route on` writes at `.claude/skills/<skill>/SKILL.md`, each description opening on `Generated by purlin:route`: for `spec`, `spec-from-code` and `sign`, a body that starts a `purlin:runner` subagent on the model with `$ARGUMENTS` and sends the person's answers to it with `SendMessage`; for each other skill but `init`, front matter naming `model:` and a body running `purlin:<skill>` with `$ARGUMENTS`
- RULE-4: The format says where a project skill's model is read: the `skills` entry of `.purlin/routing.json` for the skill's tier before the skill's own `tier:`, and the `tiers` of `.purlin/routing.local.json` before those of `.purlin/routing.json`
- RULE-5: The format's part "The hand-off" says a skill that asks the person runs whole on a `purlin:runner` subagent, every answer sent to the same subagent, and that a skill another skill runs takes the model already running
- RULE-6: The format gives the hand-off message, a fenced block whose lines open on `Command:`, `Goal:`, `Model:`, `Context:`, `Previous:`, `Read:`, `Rules:` and `Return:`, in that order
- RULE-7: No Purlin skill names "The hand-off": the step lives in the project skills alone
- RULE-8: The runner agent's front matter names `tools: Skill, Read, Write, Edit, Bash, PowerShell`, and its text says the model is chosen and it does not route again
- RULE-9: The agent definition has a part `Model routing` naming `references/formats/routing_format.md`, "The project skills" and "The hand-off", and does not restate the hand-off message
- RULE-10: The format says the model in an `@ai(...)` tag is not routed, and that the audit's planted bugs are written on the `performance` model
- RULE-11: The hand-off form runs `purlin:<skill>` in the session, starting no subagent, where the session already runs on the skill's model
