# Anchor: security_no_dangerous_patterns

> Type: security
> Global: true
> Description: The dangerous patterns no executable file under `scripts/` may carry, in
>   the form each of the six file types the scope names spells them, plus the argv
>   hardening that keeps a repository-supplied string out of git's option position. The
>   scope names file types `scripts/` does not hold today, so a file in one of them is
>   watched from the day it arrives. The anchor is global: every feature's code lives
>   under `scripts/`, so every feature counts these rules.
> Scope: scripts/**/*.py, scripts/**/*.sh, scripts/**/*.js, scripts/**/*.ts, scripts/**/*.php, scripts/**/*.cs

## Rules

- RULE-1: No file under `scripts/` executes a string as code or as a command line, in the form its language spells it: `eval(` and `exec(` in Python; `eval` and backtick substitution in shell; `eval(`, `new Function(`, `execSync(` and `child_process.exec(` in JS and TS; `eval(`, `exec(`, `shell_exec(`, `system(`, `passthru(` and backticks in PHP; `Process.Start(` given a command string in C#
- RULE-2: No file under `scripts/` opts a subprocess into a shell: no `shell=True` in Python, no `shell: true` in JS or TS, no `UseShellExecute = true` in C#
- RULE-3: No file under `scripts/` calls the builtin that hands a whole command line to the operating system shell: no `os.system(` in Python, no `system(` or `passthru(` in PHP
- RULE-4: No file under `scripts/` assigns a credential literal: no quoted value assigned to a name containing `password`, `secret`, `api_key` or `token`, in any casing, outside a test file
- RULE-5: Every subprocess launch passes an argument vector rather than a command string: a list in Python, an array in PHP `proc_open`, an args array for JS and TS `spawn` and `execFile`, and `ArgumentList` rather than an `Arguments` string in C#
- RULE-6: No repository-supplied string reaches git in option position: `--end-of-options` precedes every revision argument, `--` precedes every path argument, and a `> Source:` value that begins with `-` or names an `ext::` or `fd::` transport is refused before any subprocess starts, with the status line saying which

## Proof

- PROOF-1 (RULE-1): Every file under `scripts/` ending `.py`, `.sh`, `.js`, `.ts`, `.php` or `.cs` is read with its comment-only lines set aside, and none holds a form its language names: `eval(` or `exec(` in a `.py` file; `eval` at the start of a line or after `;`, `&` or `|`, or any text between two backticks, in a `.sh` file; `eval(`, `new Function(`, `execSync(` or `child_process.exec(` in a `.js` or `.ts` file; `eval(`, `exec(`, `shell_exec(`, `system(`, `passthru(` or any text between two backticks in a `.php` file; `Process.Start(` followed by a quoted string in a `.cs` file; a space before the `(` still counts. A line that is only a comment naming `eval(` is not counted, while a line of code that ends in a comment is read whole, so a call hidden behind a trailing comment still fails, and the failure names the file and the form it found
- PROOF-2 (RULE-2): Every file under `scripts/` ending `.py`, `.js`, `.ts` or `.cs` is read whole, comments included, and none holds its language's request for a shell: `shell=True` in a `.py` file, `shell: true` in a `.js` or `.ts` file, `UseShellExecute = true` in a `.cs` file, with any spacing around the `=` or `:`. `shell=False` is not counted, while a comment that writes `shell=True` fails as code does, and the failure names the file and the form it found
- PROOF-3 (RULE-3): Every file under `scripts/` ending `.py` or `.php` is read with its comment-only lines set aside, and none holds `os.system(` in a `.py` file, or `system(` or `passthru(` in a `.php` file, with or without a space before the `(`. A line that is only a comment naming `os.system(` is not counted; one of these forms in a line of code fails, and the failure names the file and the form it found
- PROOF-4 (RULE-4): Every file under `scripts/` ending `.py`, `.sh`, `.js`, `.ts`, `.php` or `.cs`, other than one whose name begins `test_`, is read with its comment-only lines set aside, and none gives a name ending in `password`, `secret`, `api_key` or `token`, in any casing, a quoted value of one character or more with `=`, as `API_KEY = "abc"` or `db_password='x'` would. An empty quoted value, a comparison with `==` and a file named `test_<anything>` are not counted; an assignment that is counted fails, and the failure names the file and the word it matched
- PROOF-5 (RULE-5): Every file under `scripts/` ending `.py`, `.php`, `.js`, `.ts` or `.cs` is read with its comment-only lines set aside, and every launch in it is handed a list written in place: the first argument of each Python `subprocess.run`, `subprocess.call`, `subprocess.check_call` and `subprocess.check_output` opens with `[` or `*`, the first argument of each PHP `proc_open(` opens with `[`, the second argument of each JS or TS `spawn`, `spawnSync`, `execFile` and `execFileSync` opens with `[`, and no `.cs` file sets `.Arguments` to a quoted string. `subprocess.run("git status")` fails, and so does `subprocess.run(cmd)`, whose argument is a name rather than a list; the failure names the file
- PROOF-6 (RULE-6): A project holds four anchors whose `> Source:` values are `--upload-pack=/bin/echo`, `ext::sh -c "touch /tmp/purlin-pwned"`, `fd::7` and a local repository holding one commit, and the project's status is read. The status text reads `(source rejected: begins with "-")`, `(source rejected: names an ext:: transport)` and `(source rejected: names an fd:: transport)`, and none of the three refused values appears in any command run while the status was read. The local repository is still listed with `git ls-remote`, at least once, and each such command carries `--end-of-options` immediately before the repository's path; at least one git command carries a path, `specs/` or a file under it or ending `.md`, and each that does carries `--` immediately before its first path
